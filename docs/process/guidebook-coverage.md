# 장소 사진과 조사 범위 개선

사용자 요청: 새 여행을 만들 때도 장소 사진·해설·메뉴 정보가 더 잘 채워지도록 시스템 전체를 개선한다.

| 항목 | AI가 처음 준 것 | 내가 바꾼 것 | 바꾼 이유 |
| --- | --- | --- | --- |
| 사진 검색 | 한국어 장소명은 한국어 문서에서만 검색 | 영어·현지어 검색명과 실제 방문 도시를 생성해 추가 검색 | 실제 검증에서 영어 문서에 있는 사진을 한국어 검색이 놓쳤음 |
| 장소 구분 | 숙박지·경유지가 섞인 날짜 도시명 | 장소별 방문 도시와 명확한 이름을 별도로 사용, 이름·거리 대조 유지 | 다른 도시의 동명 장소나 근처 역 사진을 잘못 붙이지 않도록 |
| 조사 자료 | 일정 작성 전 조사, 각 절의 앞부분 위주 | 일정 확정 후 지역 문서 최대 3개 추가 조사, 방문 장소가 나온 문단 우선 선택 | 관광지와 음식점 정보가 문서 뒤에 있으면 누락되던 문제 개선 |
| 자동 보관 | 해설이 있을 때만 사진 자동 검색, 별도 보관 필요 | 해설 없이도 장소명이 있으면 자동 검색, 새 사진 연결 후 브라우저 보관 | 생성한 여행책을 다시 열어도 사진이 유지되도록 |

## 검증과 한계
- 단위 테스트 112개 통과, 1개 건너뜀. 추가 자료 출처가 새 여행 생성의 검토 단계까지 전달되는지, 추가 조사 장애 시 기존 내용이 유지되는지 검증했습니다.
- PC·모바일에서 자동 검색명 전달, 사진 자동 보관·새로고침 후 재열람, 해설·맛집 탭 검증 4개 통과. 기존 지도 관련 검증 4개도 통과했습니다.
- 실제 공개 API에서 한국어 ‘후나오카 온천’과 영어 검색명으로 `Funaoka Onsen` 사진 및 `CC BY 3.0` 이용 조건이 반환되는 것을 확인했습니다. 다른 장소, 먼 지역의 동명 장소, 허용하지 않은 사진 이용 조건은 테스트에서 거절했습니다.
- 개발 모드에서 화면이 재마운트될 때 사진 검색이 중단되던 문제를 수정했습니다. 사용자가 활동 이름을 바꾸면 이전 자동 검색명도 제거합니다.
- 재사용 가능한 사진과 공개 자료가 없는 장소는 여전히 누락될 수 있습니다. 사진 누락·조회 실패 수를 표시하며, 추가 조사 실패도 안내합니다. 현재 영업·메뉴·예약 가능 여부를 보장하지 않습니다.
- 새 여행 전체를 실제 AI로 처음부터 생성하는 재검증은 별도입니다. 이번에는 생성 파이프라인 테스트와 실제 사진 조회를 구분해 확인했습니다.

구현 참고: [MediaWiki 검색 API](https://www.mediawiki.org/wiki/API:Search/en), [문서 정보와 사진 조회](https://www.mediawiki.org/wiki/API:Page_info_in_search_results/en). 사진은 기존 Commons 출처·저작자·라이선스 검증을 유지합니다.
